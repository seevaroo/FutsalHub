1. Ringkasan Eksekutif (Executive Summary)

FutsalHub adalah platform web reservasi lapangan futsal modern yang dirancang untuk mengotomatisasi seluruh siklus bisnis penyewaan lapangan olahraga. Platform ini menghubungkan pelanggan (pemain/komunitas futsal) dengan pihak pengelola arena (administrator/kasir) melalui antarmuka yang intuitif, cepat, dan transparan.

Tujuan Utama Produk (Product Goals)
Meniadakan risiko bentrok jadwal (double-booking), menggantikan pencatatan manual berbasis buku/WhatsApp dengan sistem real-time, memfasilitasi opsi pembayaran multi-kanal (QRIS digital & Cash di kasir), serta menyajikan laporan keuangan dan okupansi lapangan yang akurat bagi pengelola.

1.1 Masalah Bisnis & Solusi FutsalHub

Tantangan Operasional Dampak Negatif Manual Solusi Terintegrasi FutsalHub
Jadwal Tumpang Tindih Dua tim datang di jam yang sama akibat kelalaian admin manual; komplain pelanggan tinggi. Slot Locking Engine: Slot otomatis terkunci saat reservasi dibuat; validasi ketersediaan real-time hingga level detik.
Verifikasi Pembayaran Lambat Bukti transfer tercecer di chat WhatsApp pribadi kasir tanpa nomor referensi yang jelas. Dedicated Verification Workflow: Bukti QRIS tersimpan rapi per ID pesanan lengkap dengan modal inspeksi resolusi tinggi.
Keterbatasan Info Lapangan Penyewa tidak mengetahui spesifikasi lantai (vinyl, sintetis, interlock) dan fasilitas sebelum datang. Interactive Catalog & Showcase: Detail spesifikasi lantai, sertifikasi FIFA, dan 8 fasilitas arena tersaji transparan.
Rekap Pendapatan Rumit Penyusunan laporan bulanan memakan waktu berhari-hari; risiko salah hitung kas tinggi. One-Click Reporting & Print: Filter periode fleksibel dan format cetak resmi siap audit fisik.

3. Alasan Pemilihan Stack Teknologi (Technical Rationale)

Keputusan arsitektur teknologi didasarkan pada pertimbangan keandalan transaksi, keamanan data, efisiensi resource, dan kemudahan pemeliharaan:

Backend Kenapa Laravel 13 & PHP 8.5?
1. Kecepatan Pengembangan & Fitur Terkini: Laravel 13 berjalan di atas PHP 8.5.12 dengan optimasi performa kompilasi JIT, efisiensi memori, ekosistem middleware otorisasi berbasis peran (Role-Based Access Control), dan validasi request yang ketat.
2. Keamanan Tingkat Lanjut: Perlindungan otomatis terhadap ancaman web terpopuler (CSRF Token, XSS Sanitization, SQL Injection via PDO Prepared Statements, serta Bcrypt Password Hashing).
3. Eloquent ORM: Mempermudah manajemen relasi antar tabel (User, Booking, Field, Payment) secara elegan dengan transaksi aman (DB::transaction).
UI Styling Kenapa Tailwind CSS v4?
1. Utility-First & Kebebasan Desain: Menghilangkan kebutuhan menulis ribuan baris CSS manual dan mencegah bentrok nama class (CSS specificity).
2. Ukuran Bundle Sangat Ringan: Tailwind v4 menggunakan engine kompilasi berbasis Rust/Lightning CSS yang mengekstrak hanya class yang dipakai (zero runtime overhead).
3. Konsistensi Tema Olahraga: Memungkinkan perpaduan palet warna dark luxury (Slate 950) dan hijau olahraga (Emerald 400/500) yang memikat dan modern.
Frontend Kenapa Blade + Vanilla JS?
1. Performa Server-Side Rendering (SSR): Halaman langsung dikirim utuh dari server ke browser tanpa menunggu loading berat bundle JavaScript (seperti React/Vue).
2. Efisiensi Resource: Vanilla JS tanpa library eksternal menjaga ukuran halaman di bawah 50KB untuk JavaScript, menghasilkan waktu buka (First Contentful Paint) sangat instan.
3. Kemudahan Maintenance: Tidak memerlukan pengaturan API decoupled yang kompleks; logika antarmuka tetap menyatu dengan template Blade.
Database Kenapa MySQL Relasional?
1. Integritas ACID: Reservasi lapangan menuntut konsistensi absolut di mana pembayaran dan penguncian slot tidak boleh mengalami race condition.
2. Relasi Kompleks yang Terstruktur: Relasi satu booking dengan banyak jam sewa (1 to Many) dan satu booking ke satu bukti pembayaran (1 to 1) paling ideal dimodelkan dalam RDBMS.
3. Foreign Key Constraints: Mencegah inkonsistensi data ketika pengguna atau lapangan dimodifikasi melalui aturan ON DELETE SET NULL atau CASCADE.

4. Perincian Fitur Aplikasi (Product Functional Specifications)

Aplikasi FutsalHub terbagi menjadi dua hak akses utama: Customer Portal (Penyewa) dan Admin Arena Management (Pengelola).

4.1 Modul Pengguna & Autentikasi (Authentication & User Lifecycle)

  • Registrasi Mandiri (Customer): Pendaftaran akun baru dengan validasi email unik, nomor telepon WhatsApp, dan enkripsi kata sandi menggunakan algoritma hashing aman.
  • Login & Session Management: Autentikasi dengan perlindungan CSRF, opsi 'Remember Me', dan redirect cerdas sesuai peran (Admin dialihkan ke Dashboard, Customer ke Beranda).
  • Manajemen Profil Pengguna: Fitur memperbarui identitas profil (Nama lengkap, nomor telepon, alamat email), mengganti kata sandi, serta mengunggah avatar/foto profil kustom.
  • Hapus Akun Permanen (Self-Service Deletion): Pengguna dapat menghapus akunnya sendiri melalui dialog konfirmasi bahaya ganda. Sistem mengosongkan kredensial login (SET NULL pada foreign key), namun snapshot nama dan nomor telepon tetap diarsipkan pada rekaman booking historis untuk kepentingan audit administratif arena.

4.2 Modul Customer (Antarmuka Penyewa Lapangan)

Beranda Home & Showcase Arena
• Hero Banner Dinamis: Visual modern dengan logo FutsalHub, teks pengantar, tombol CTA, dan ilustrasi lapangan futsal transparan tanpa kanvas.
• Edukasi Karakteristik Lantai: Menjelaskan secara rinci keunggulan 3 tipe lantai (Vinyl Standar FIFA, Rumput Sintetis Monofilamen, dan Interlock Polimer).
• 8 Fasilitas Unggulan Arena: Ruang Ganti & Loker, Shower Air Hangat, Parkir Luas & Aman, Kafetaria & Minuman, Bola & Rompi Gratis, Free WiFi Cepat, Lampu LED Stadium, dan Scoreboard Digital.
• Preview Lapangan & Detail Modal: Popup interaktif berisi spesifikasi lengkap, dimensi lapangan, fasilitas per lapangan, dan tarif sewa.
Katalog Pencarian & Filter Lapangan
• Filter Tipe Permukaan: Tombol pill satu klik untuk memfilter: Semua Lapangan, Vinyl, Rumput Sintetis, dan Interlock Polimer.
• Pencarian Cepat (Instant Search): Kolom input pencarian nama lapangan yang langsung memfilter hasil.
• Status Lapangan Real-time: Indikator status ketersediaan (Tersedia atau Sedang Dalam Perawatan/Perbaikan).
• Direct Booking Action: Tombol 'Pesan Jam' langsung mengarahkan ke formulir kalender reservasi lapangan bersangkutan.
Reservasi Booking & Real-Time Slot Engine
• Pemilihan Tanggal Fleksibel: Proteksi tanggal masa lalu (hanya dapat memilih tanggal hari ini ke depan).
• Pencegahan Slot Kedaluwarsa: Pada hari H, jam-jam yang sudah terlewat otomatis menjadi tidak aktif (disabled) dan berwarna abu-abu.
• Pencegahan Double-Booking: Slot yang telah dipesan atau sedang dalam proses verifikasi langsung terkunci secara real-time via API.
• Multi-Slot Selection: Penyewa dapat memilih lebih dari satu jam bertanding berturut-turut dengan kalkulasi subtotal dan total biaya otomatis.
Pembayaran Checkout & Pembatalan Mandiri
• Metode Pembayaran QRIS: Menampilkan QR Code statis arena, tata cara transfer e-wallet/m-banking, dan form upload bukti transaksi (JPG/PNG).
• Metode Pembayaran Cash: Opsi bayar tunai langsung di kasir arena sebelum bertanding.
• Batalkan Pesanan Mandiri: Tombol batal di bagian bawah halaman checkout jika penyewa ingin membatalkan booking sebelum pembayaran diverifikasi.
Riwayat Riwayat Pesanan & Invoice Digital
• Filter Status Pemesanan: Menyaring riwayat pesanan berdasarkan: Semua, Menunggu Pembayaran, Menunggu Verifikasi, Terkonfirmasi, Selesai, Dibatalkan, dan Ditolak.
• Digital Invoice & Receipt: Halaman invoice resmi berdesain elegan dengan nomor unik, barcode, rincian biaya per jam, dan instruksi penukaran di meja resepsionis.
• Status Badge Dinamis: Warna badge responsif (Kuning: Menunggu Verifikasi, Hijau: Terkonfirmasi, Merah: Dibatalkan/Ditolak).
UI System Dynamic Island & Bell Notification
• Dynamic Island Floating Notification: Notifikasi flash status mengambang di bagian atas tengah layar bergaya iOS/Dynamic Island dengan animasi halus, ikon status, dan auto-dismiss setelah 4 detik.
• Notifikasi Lonceng (Header Bell): Indikator dropdown interaktif yang memuat riwayat booking yang dibatalkan oleh pengguna maupun yang ditolak oleh admin.

4.3 Modul Administrator (Pengelola Arena)

Portal khusus pengelola arena untuk memonitor seluruh operasional bisnis dan keuangan:

Sub-Modul Admin Fungsi & Kemampuan Teknis Manfaat bagi Manajemen Arena
Dashboard Utama Statistik kartu metrik: Total Pendapatan, Total Booking Sukses, Pesanan Perlu Verifikasi, dan Lapangan Aktif beserta ringkasan transaksi terbaru. Memberikan visibilitas langsung terhadap performa pendapatan dan beban antrean verifikasi harian.
Master CRUD Lapangan Tambah lapangan baru, edit nama, jenis lantai, tarif sewa per jam, upload foto representasi, ubah deskripsi, dan set status (Tersedia / Perbaikan). Fleksibilitas penuh dalam mengatur ketersediaan fisik lapangan dan pembaruan tarif sewa periodik.
Verifikasi Pembayaran Daftar transaksi pending. Fitur inspeksi bukti QRIS resolusi penuh via modal popup, aksi Setujui (Approve), dan aksi Tolak (Reject). Opsi 'Selesaikan Cash' untuk pembayaran di kasir. Menjamin setiap booking yang masuk telah membayar sah dan mengontrol kas fisik arena tanpa selisih.
Laporan Reservasi & Cetak Filter laporan berdasarkan rentang tanggal kalender, status pesanan, dan filter lapangan. Dilengkapi tampilan cetak khusus (@media print) siap cetak fisik atau export PDF. Mempermudah pembukuan akuntansi, evaluasi jam sibuk (peak hours), dan pelaporan ke pemilik modal arena.

5. Arsitektur Basis Data (Database Schema & Relasi)

Struktur relasi data dirancang dengan normalisasi tingkat ketiga (3NF) guna menjamin konsistensi dan integritas referensial:

Entitas / Tabel Atribut Utama Keterangan & Relasi Data
users id, name, email, phone, password, role, avatar Menyimpan akun pengguna. role: 'admin' atau 'customer'. Relasi: 1 to Many ke bookings.
fields id, name, type, price_per_hour, description, image, status Master data lapangan. type: vinyl, sintetis, interlock. Relasi: 1 to Many ke bookings.
time_slots id, start_time, end_time Master jam operasional per 60 menit (08:00 - 22:00 WIB). Relasi: 1 to Many ke booking_details.
bookings id, booking_code, user_id, customer_name, customer_phone, field_id, booking_date, total_price, status, cancelled_by Header reservasi. status: pending_payment, pending_verification, confirmed, completed, cancelled, rejected.
booking_details id, booking_id, slot_id, price Item rincian jam sewa per booking (mendukung pemesanan multi-slot dalam 1 transaksi).
payments id, booking_id, payment_method, proof_image, paid_at, status Rekaman transaksi pembayaran. payment_method: qris, cash. Relasi: 1 to 1 ke bookings.

6. Persyaratan Non-Fungsional (Non-Functional Requirements)

Keamanan Security & Data Integrity
• CSRF & XSS Protection: Semua formulir transaksi dilindungi token CSRF dan rendering Blade melakukan escaping karakter berbahaya secara otomatis.
• Password Hashing: Pengacakan sandi menggunakan enkripsi Bcrypt / Argon2.
• Role Middleware: Akses rute /admin/* divalidasi ketat oleh middleware role:admin.
Performa Speed & Responsiveness
• Sub-Second Loading: Kompilasi view Blade dan minimalisasi aset menghasilkan kecepatan load halaman di bawah 1 detik.
• Mobile-First Design: Antarmuka beradaptasi sempurna pada layar smartphone, tablet, hingga monitor desktop ultra-wide.
• Print-Optimized: Tata letak invoice dan laporan otomatis menanggalkan elemen navbar/sidebar saat dicetak.
Rencana Pengembangan Masa Depan (Roadmap Ekstensi)
1. Integrasi Payment Gateway Otomatis (Midtrans / Xendit Snap API) untuk verifikasi QRIS instan tanpa upload struk manual.
2. Notifikasi WhatsApp Gateway (Fonnte API) otomatis untuk pengiriman tiket invoice langsung ke nomor penyewa.
3. Sistem Poin Loyalitas & Turnamen Mini Bracket bagi komunitas futsal terdaftar.
